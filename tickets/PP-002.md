## Objective and scope

Assess candidate non-production targets against the confirmed single-instance SQLite and artifact-storage requirements, provide suitability evidence, and seek an explicit Product Owner decision under OPS-01. Record a blocker if no suitable target can be confirmed.

The assessment covers one active application instance with one API and one separate worker sharing a persistent local SQLite file and protected artifact directory across restarts/redeployments, plus protected secrets, TLS, health checks, logs/usage visibility, coherent backup/restore, and rollback support.

This is an early target-suitability decision only. It does not perform deployment, create an account or cloud resource, approve a proposed topology or provider without explicit Product Owner confirmation, or change the one-instance/local-storage constraints. The preferred Linux VM/Docker Compose topology remains Proposed unless separately approved.

## Decisions to be resolved

- OPS-01: whether a specific non-production target is suitable and approved for the PRD-required deployment and rollback demonstration.
- Keep the selected target, provider, and topology status explicit. The proposed Linux VM/Docker Compose shape and every provider remain unapproved until the Product Owner confirms them.

## Testable acceptance criteria

1. The ticket records candidate target(s), evidence source(s), and a requirement-by-requirement suitability assessment for the single API/worker instance, shared persistent local SQLite and artifact storage, restart/redeploy persistence, protected secrets, TLS, health/log/usage visibility, backup/restore, and rollback.
2. Material unknowns, limitations, account/access requirements, and cost considerations are stated without claiming unsupported provider capabilities.
3. The assessment ends with a concrete decision request and records the Product Owner's explicit disposition, or records that no target is confirmed and leaves OPS-01 Proposed/open.
4. If approved, the Decision Register and relevant deployment/operations documentation record the target and evidence consistently; the Implementation Plan reflects any changed deployment gate.
5. No deployment, provider resource, account, or unapproved topology is created or represented as approved by this ticket.

## Verification and review requirements
