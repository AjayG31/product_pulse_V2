## Objective and scope

Record evidence-based choices for implementation tools while preserving the approved ProductPulse application technologies. Resolve the conflict between the prior PRD hosted-CI wording and the Product Owner's explicit exclusion of GitHub Actions by documenting the approved local automated verification process through PRD change RC-01.

In scope:

- Record selected Python and React packages, frontend routing/state, backend/API and frontend test tools, local verification runner, security/performance checks, relational data-access/migration tools, and background-worker library.
- Record the Product Owner's approval of repeatable local PowerShell scripts, a documented pre-merge checklist, exact-revision evidence, and failure/restoration demonstration in place of hosted CI merge gates.
- Record that GitHub Actions and Playwright are excluded and that no separate browser E2E framework is selected.
- Align PRD, Decision Register, Technical Stack, Architecture, Evaluation Plan, Implementation Plan, Definition of Done, and affected security/API/data-model evidence references.
- Preserve existing application technologies, automated tests, security requirements, evaluation definitions, and pending calibration decisions.

Out of scope: creating application code, automated tests, local scripts, migrations, CI workflows, configuration defaults, or tool installations; changing React + TypeScript + Recharts, FastAPI, SQLite as the sole primary database, versioned migrations, or one separate worker; changing unrelated product requirements; selecting a deployment host, email sink, model, retry values, or other decisions assigned elsewhere.

## Recorded selections and decisions

- ARC-01: React Router, MUI, TanStack Query, and React state/context within the unchanged React + TypeScript + Recharts application baseline.
- ARC-02: CPython 3.12 with uv for the single FastAPI backend.
- ARC-03: SQLAlchemy and Alembic for SQLite data access and versioned migrations.
- ARC-04: one separate standard-library Python polling worker over approved SQLite job/outbox records.
- Backend/API tests: pytest and FastAPI TestClient.
- Frontend tests: Vitest and React Testing Library. No Playwright or separate browser E2E framework.
- Local checks: repeatable PowerShell scripts, documented pre-merge checklist, exact-revision commands/results/evidence.
- Security/performance checks: Bandit, pip-audit, npm audit, and later-stage OWASP ZAP Baseline and Locust.
- ARC-06: no GitHub Actions or hosted CI merge gates. Local automated verification replaces the prior CI execution requirement under PRD change RC-01. The approved functional, security, and evaluation checks remain required; pending metric thresholds remain pending.
- Coverage reporting package and numeric threshold remain unselected and are not prerequisites to PP-001 closure or PP-010.
